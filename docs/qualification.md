# Qualification and release evidence

[Return to the module documentation index](README.md).

This template consumes `mosaic-flow` release `MF20260910V1`, resolved by the
gitlink to commit `0bd222f827afd802944d5f7e6ebc2ccc3a96f7ea`. The module owns
the policies and design fixtures below. The pinned methodology owns schema
validation, execution, status semantics, and release indexing.

## Evidence classes

| Class | Template use | Signoff boundary |
| --- | --- | --- |
| Portable | Lint, elaboration, generic synthesis, formal, equivalence, simulation, PyUVM, coverage, campaigns, and static intent | Required public CI evidence, not technology signoff |
| Optional physical | Containerized ORFS on public Nangate45 | Exploratory place-and-route evidence, not foundry signoff |
| Commercial | VCS, VC Lint, CDC, DFT, VC LP, Design Compiler, PrimeTime, and PrimePower | Disabled until a licensed site qualifies the adapter and project inputs |
| Signoff | Project-selected PDK, libraries, corners, extraction, STA, power, CDC, DFT, low-power, DRC, and LVS | Must run in the authorized implementation environment |

Every canonical enabled flow must write `PASS`. A disabled flow is an approved
policy `SKIP`. `FAIL`, `BLOCKED`, missing evidence, an unauthorized skip, or
stale evidence rejects release-manifest generation.

## Coverage policy

`config/coverage-policy.json` declares independent minimum line, branch,
toggle, and user coverage, required named coverpoints, and formal cover
reachability. The template reuses native coverage generated by normal Verilator
simulation through `COVERAGE_QUALIFICATION_SOURCE=verilator_sim`. It does not
duplicate SVA or the HDL coverage wrapper.

PyUVM functional coverage remains a separate JSON artifact. It describes
transactions and scenarios observed by the Python verification environment and
must not be combined numerically with structural HDL coverage.

```sh
make open-sim
make open-formal
make open-coverage
```

The CI control script raises a named-coverpoint requirement beyond the collected
result and proves that deficient evidence fails qualification.

## Negative and four-state campaigns

`config/qualification-campaigns.json` declares commands as arrays, expected
results, required diagnostic expressions, and failure classes. The negative
campaign contains successful simulation and equivalence controls before testing
an injected capture fault, an illegal width, and a deliberately inequivalent
netlist. Mutations stay under `verif/mutations/` and are never compiled by the
normal file lists.

The four-state campaign compiles
`verif/tb/mosaic_module_four_state_tb.sv` with pinned Icarus. One control proves
that X and Z stimulus reaches `enable_i` with the monitor disabled. The paired
case requires the monitor to reject both values with the expected diagnostic.

```sh
make open-negative
make open-four-state
```

Evidence is isolated below `reports/<flow-id>/<case>/` and
`work/<flow-id>/<case>/`. Profile and module names are inserted before the flow
ID when selected. `.github/scripts/check-qualification-controls.sh` also proves
that escaped mutations, unavailable tools, and disabled unknown-value monitors
cannot qualify.

## Portable static intent

`config/static-intent.json` identifies this example as a sequential design. It
requires `clk_i`, uncertainty, input and output delays, the reviewed asynchronous
reset false path, agreement between synthesis and physical SDC, and an
always-on UPF domain. Isolation, retention, level shifting, and power switches
are not required by this example.

```sh
make open-static-intent
```

The CI controls reject missing, duplicate, conflicting, broad, incomplete,
forbidden, and unsupported SDC or UPF intent. This parser-backed gate has no
timing graph, voltage model, cell library, or CDC analysis. It is not STA, CDC,
IEEE 1801, VC LP, or physical signoff.

## Parameter profiles

The non-default example at `config/examples/parameter-profiles.json` exercises
minimum, nominal, and wide `DATA_WIDTH` values. Testbench and formal tops expose
the same parameter and propagate it to the DUT. Supported adapters receive the
profile override through their native parameter mechanism.

```sh
make PARAMETER_PROFILE_MANIFEST=config/examples/parameter-profiles.json \
  profile-manifest-check
make PARAMETER_PROFILE_MANIFEST=config/examples/parameter-profiles.json \
  profile-matrix
make PARAMETER_PROFILE_MANIFEST=config/examples/parameter-profiles.json \
  all-profiles PROFILE_JOBS=3
```

`PROFILE_JOBS` bounds parallel execution. The aggregate result is
`reports/parameter-profile-summary.json`. Each child receives isolated
`reports/<profile>/` and `work/<profile>/` trees and the aggregate fails when a
child fails or lacks evidence.

## Multi-module example

`docs/examples/multi-module/config/modules.json` demonstrates the versioned
`mosaic-modules-v1` registry without turning this single-module repository into
a multi-module project. The selected `counter` and `fifo` entries resolve their
matching files under `config/modules/`.

```sh
python3 mosaic-flow/ci/module_manifest.py validate \
  --manifest docs/examples/multi-module/config/modules.json \
  --module-root docs/examples/multi-module
python3 mosaic-flow/ci/module_manifest.py matrix \
  --manifest docs/examples/multi-module/config/modules.json \
  --module-root docs/examples/multi-module
```

The CI script emits the module and parameter-profile matrices twice and compares
them byte for byte before running the bounded profile regression.

## OpenROAD evidence

The physical job enables `openroad` explicitly and uses the immutable ORFS
image recorded by the methodology release. The module supplies
`flows/openroad/config.mk`, `timing.sdc`, and `evidence-policy.json`.

```sh
make FLOW_openroad=enabled \
  OPENROAD_EXECUTION_MODE=container \
  open-physical
```

The policy requires nonempty final DEF, GDS, ODB, SDC, and netlist artifacts.
It also requires zero setup, hold, slew, fanout, capacitance, and routing
violations for the representative fixture. `reports/openroad/evidence.json`
records the image reference and digest, platform, flow variant, input and
artifact hashes, sizes, and parsed metrics. The container runs as the invoking
UID and GID.

For a qualified local ORFS checkout, set `OPENROAD_EXECUTION_MODE=local` and
`OPENROAD_FLOW_ROOT=<checkout>`. Do not replace the CI image with a floating tag.

## Release manifest

Run every flow required by the selected policy before generating a manifest:

```sh
make \
  MODULE_REVISION="$(git rev-parse HEAD)" \
  METHODOLOGY_REVISION="$(git -C mosaic-flow rev-parse HEAD)" \
  RELEASE_EXECUTION_CONTEXT=native \
  release-manifest release-manifest-validate
```

The manifest hashes declared RTL, verification layers, file lists, constraints,
waivers, policies, and configuration. It indexes canonical status, normalized
coverage, PyUVM functional coverage, static-intent findings, campaign summaries,
and physical evidence when enabled. It records the selected module, profile,
technology, execution context, revisions, and exact tool identities.

A dirty module or methodology tree fails by default. During local development,
`RELEASE_ALLOW_DIRTY=enabled` permits generation while recording the dirty
state. Such a manifest is diagnostic only and must not be published as release
evidence. CI always supplies explicit revisions and validates clean source and
the pinned methodology checkout.
